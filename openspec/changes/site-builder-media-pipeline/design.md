# Phase C: Media Pipeline Design

## Storage Architecture (ADR: Local Storage vs IndexedDB vs Blob)
**Decision:** Use `IndexedDB` (via `idb` or similar lightweight wrapper) for transient media blobs during local previews.
**Justification:** 
- `localStorage` has a strict ~5MB limit and blocks the main thread, making it entirely unsuitable for storing Base64/binary images.
- Cloud Object Storage (e.g., Vercel Blob) adds unnecessary latency and costs for drafts that may never be exported.
- `IndexedDB` supports storing native `Blob` and `ArrayBuffer` objects asynchronously with virtually no quota limits for standard draft usage.
- The `MediaAssetStore` interface will abstract this, allowing a future swap to a cloud backend if the architecture changes to multi-user.

## Provider Abstractions
- **Pexels:** Primary Licensed Media Provider. Allows downloading for bundled projects. Requires attribution.
- **Pixabay:** Fallback Licensed Media Provider. Strict cache rules, prohibits hotlinking (perfect for ZIP bundles).
- **Unsplash:** REJECTED for MVP. Unsplash API Terms explicitly mandate hotlinking and dynamic download tracking, which fundamentally conflicts with the standalone, air-gapped `site.zip` requirement.

## Contracts & Data Structures
A new sidecar contract `ResolvedMedia` (or `MediaManifest`) will be created to store media provenance without bloating the `GeneratedSiteBlueprint`.
```typescript
interface ResolvedMediaAsset {
  id: string; // Maps to MediaPlan item ID
  provider: 'pexels' | 'pixabay' | 'client' | 'ai';
  providerAssetId: string;
  sourceType: 'licensed' | 'realBusinessMedia' | 'generated-illustration';
  mimeType: string;
  hash: string;
  localAssetUrl: string; // Object URL from IndexedDB during preview
  attribution?: string;
  alt: string;
  decorative: boolean;
}
```

## Security & Protection
- **API Keys:** Kept strictly server-side.
- **SSRF:** Providers return structured JSON. The backend fetches the raw bytes and returns them to the client. No client-side fetching of arbitrary URLs generated by an LLM.
- **Decompression/Size Limits:** Max 5MB per image. Allowed types: `image/jpeg`, `image/png`, `image/webp`. SVG is strictly rejected due to XSS risks.
